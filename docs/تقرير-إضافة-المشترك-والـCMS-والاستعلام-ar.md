## نظرة عامة على النظام

النظام عبارة عن **لوحة تحكم إدارية** (تُدار من المتصفح بالكامل، والبيانات تُحفظ محليًا على جهاز المستخدم وبخمسة مخازن منفصلة). تعتمد اللوحة على ثلاثة مكوّنات مترابطة:

| المكوّن | الدور | أين يظهر |
|---------|-------|----------|
| **إضافة المشترك** | إدخال بيانات المستثمر الجديد مع تصميم تطبيقه الخاص | تبويب «إضافة مشترك» |
| **نظام CMS** | استوديو تصميم «تطبيق العميل» لكل مشترك — 28 قسمًا | داخل قسم إضافة المشترك، أسفل النموذج |
| **نظام الاستعلام** | البحث عن مشترك وعرض ملفه + فتح تطبيقه + العمليات والسحب | تبويب «نظام الاستعلام عن الأرباح» (Admin Panel) |

**الفكرة الجوهرية:** كل مشترك هو «تطبيق» مستقل. عندما تُدخل بيانات مشترك في «إضافة المشترك»، فإنك في نفس الوقت تبني تطبيق العميل الخاص به (من خلال CMS). وعندما يبحث أحدهم عنه في «نظام الاستعلام»، تظهر بياناته المُدخلة، ثم يمكنه فتح «تطبيق العميل» الكامل الذي صمّمته.

**ثلاث نقاط ربط جوهرية سيتكرر ذكرها:**
1. المشترك يحمل **تصميم CMS الخاص به** كجزء من بياناته.
2. العمليات تُربط بالمشترك **عبر اسمه النصي** (وليس رقم تعريف).
3. تجربة «بوابة الاستعلام» (العامة) منفصلة تمامًا عن «تطبيق العميل» (الخاص بكل مشترك).

# الجزء الأول: قسم إضافة المشترك

## الوصول إلى القسم

- من القائمة الجانبية غادر إلى **«إضافة مشترك»**.
- يظهر عنوان القسم حسب تسمية النظام (يمكن تخصيصها من «لوحة إدارة النظام»)، ويُعرض الرقم الإجمالي للمشتركين المسجّلين بجواره.
- أعلى القسم يوجد **مُنشئ تجربة بوابة المشترك**، وهذا خاص بواجهة الاستعلام العامة وليس بالمشترك نفسه (يُشرح لاحقًا).

## التدفق من البداية إلى النهاية

عند دخول القسم، يمرّ المستخدم بالنموذج ثم بخيارات ما بعد الإدخال:

```
البداية
  │
  ├─ 1) إدخال حقل تلو الآخر (اختياري — كلها اختيارية)
  │
  ├─ 2) إرفاق عمليات للمشترك (اختياري)
  │
  ├─ 3) بناء/تعديل تصميم تطبيق العميل عبر استوديو CMS (28 قسمًا)
  │
  ├─ 4) الضغط على «إضافة المشترك»
  │       ├─ فحص التكرار (نفس الهاتف أو الآيبان)  → تحذير → «إضافة على أي حال»
  │       ├─ تأكيد حفظ الآيبان  → «نعم احفظ» / «لا، امسح»
  │       ├─ تأكيد حفظ رقم الحساب → «نعم» / «لا»
  │       ├─ دمج رقم الهاتف مع بادئة الدولة
  │       ├─ ترتيب عملات المبالغ (إذا المبلغ 0 تُمسح العملة)
  │       ├─ تجميع حساب النظام وعنوان المحفظة
  │       └─ حفظ المشترك + حفظ العمليات المرفقة
  │
  ├─ 5) معاينة حية (داخل نافذة / أو فتحها في تبويب جديد)
  │
  └─ 6) بعد الحفظ: تظهر رسالة نجاح، يُعاد تصفير النموذج،
         ويظهر المشترك الجديد في «قائمة المشتركين» أسفل الصفحة
```

> **ملاحظة هامة:** كل الحقول اختيارية، والنظام يعرض في الاستعلام **فقط** البيانات المُدخلة وغير المخفية. لذلك قد تظهر بيانات معينة لمشترك ولا تظهر لمشترك آخر.

## حقول النموذج بالتفصيل

| المجموعة | الحقل | الشرح |
|----------|-------|-------|
| **الهوية والاتصال** | اسم المشترك | النص الكامل للاسم |
| | رقم الهاتف مع البادئة | قائمة منسدلة بها علم الدولة + رمز الاتصال؛ الدول العربية ذات أولوية في الأعلى، مع بحث بالاسم أو الرمز. يُدمج الرقم مع البادئة تلقائيًا عند الحفظ |
| | إظهار/إخفاء الهاتف | زر عين (👁) يقرّر ظهور الرقم في ناتج الاستعلام |
| | رقم الآيبان (IBAN) | حقل بخط خاص، مع زر إظهار/إخفاء وزر مسح |
| | رقم الحساب البنكي | حقل إضافي بحرية، مع زر إظهار/إخفاء وزر مسح |
| **المبالغ** | مبلغ الاشتراك + عملته | قائمة عملات تضم العملات العالمية والعملات الرقمية (مع الشعارات) |

| **المحفظة** | عنوان المحفظة (ثلاث خطوات) | 1) اختيار المنصة ← 2) اختيار العملة الرقمية ← 3) إدخال العنوان (مع الشبكة) |
| **التسجيل** | تاريخ الانضمام | حقل تاريخ، يظهر فقط إذا كان مملوءًا |
| | حالة المشترك | نشط / مشترك جديد / رسوم مستحقة / توزيع أرباح / معلق / موقوف |
| **البنك** | البنك | بحث بالدولة أو اسم البنك (قاعدة بنوك عربية وخليجية مع شعارات ورموز سويفت)، مع فلاتر دولة وأعلام، أو إدخال الاسم يدويًا |

| | نص السحب | النص الذي يظهر للمشترك بعد تأكيد طلب سحب الأرباح |
| **العمليات** | سجل عمليات للمشترك (اختياري) | إضافة عمليات (نوع العملية، الحالة، المبلغ، التاريخ) قُبيل الحفظ لتُربط بسمة المشترك |
| **التصميم** | استوديو تصميم تطبيق العميل | قسم CMS الكامل (يُشرح في الجزء الثاني) |

## التحققات والتأكيدات قبل الحفظ

حتى تُحفظ البيانات بشكل نظيف وآمن، يمرّ النظام بهذه الرقابات بالترتيب:

1. **فحص التكرار:** إذا كان هناك مشترك آخر بنفس رقم الهاتف أو نفس الآيبان (في حالة الإضافة الجديدة)، تُعرض نافذة تحذير بمعلومات المشترك المكرر، مع خيار «إضافة على أي حال» أو «إلغاء».
2. **تأكيد الآيبان:** إذا أُدخِل آيبان ولم يُؤكَّد حفظه بعد، تُظهر نافذة «تأكيد حفظ رقم الآيبان؟» مع خيار «نعم، احفظ» أو «لا، امسح» (في الحالة الأخيرة يُمسح الآيبان قبل الحفظ).
3. **تأكيد رقم الحساب:** نفس منطق الآيبان، مع «نعم» أو «لا».
4. **دمج رقم الهاتف:** يُنظَّف رقم الهاتف من البادئة ثم يُعاد دمجها، وتُحفظ معه البادئة ورمز الدولة ISO.

> هذه التأكيدات تجعل المدير واعيًا بكل حقل حساس (آيبان/حساب) قبل أن يُعتمَد نهائيًا.

## الحساب الآلي ودمج البيانات

عند الحفظ، يجري النظام عدة عمليات معالجة تلقائية على القيم:

- **تنظيف العملات:** أي مبلغ قيمته صفر يُمسح معه حقل العملة ورمزها (حتى لا تبقى عملة بلا مبلغ).
- **تجميع حساب النظام:** إذا كان النوع «يدوي» تُستخدم القيمة كما هي؛ إذا كان «آيدي محفظة» يُركَّب «نوع المحفظة:القيمة»؛ إذا كان «عنوان محفظة» يُركَّب «الشبكة:القيمة».
- **تجميع عنوان المحفظة:** إذا اكتملت الخطوات الثلاث (المنصة + العملة + العنوان) يُركَّب العنوان بالشكل «المنصة|العملة|الشبكة|العنوان».
- **مزامنة اسم المشترك مع العمليات:** في حالة **التعديل**، إذا تغيّر اسم المشترك، يحدّث النظام كل العمليات التي كانت معلّقة بالاسم القديم فيُصبح اسمه الجديد (حتى لا تُفقد ربط العمليات).

## سجل العمليات المرفق بالمشترك

- يمكن إضافة عمليات قبل حفظ المشترك عبر زر «إضافة عملية».
- لكل عملية: **نوع العملية** (توزيع أرباح، اشتراك جديد، تنشيط النظام، سحب أرباح، تحويل)، **الحالة** (مكتمل، اشتراك جديد، تنشيط النظام، قيد المعالجة)، **المبلغ**، و**التاريخ**.
- تُعرض العمليات المضافة في قائمة خضراء مؤقتة بجانب القسم مع إمكانية حذف أي منها.
- عند الحفظ، تُحوَّل هذه العمليات إلى سجل عمليات حقيقي مربوط باسم المشترك، فتُظهره شاشة الاستعلام لاحقًا.

## استوديو تصميم تطبيق العميل (CMS) داخل القسم

أسفل النموذج يوجد **«استوديو تصميم تطبيق العميل — 28 قسم»** بشارة CMS. هذا هو الجزء الذي يُبنى منه «تطبيق» المشترك، ويُفصَّل في الجزء الثاني. هنا فقط نذكر أن هذا الاستوديو يعمل على **نفس بيانات المشترك** ويُحفظ معه (كجزء من كائن المشترك).

## المعاينة الحية والتصدير والبيانات التجريبية

### المعاينة الحية
- زر **«معاينة حية»** يفتح نافذة تغطي الشاشة، تعرض تطبيق العميل داخل إطار (iframe) مستقل.
- توجد أزرار تبديل حجم الجهاز: **جوال (375px) / تابلت (768px) / ديسكتوب (1280px)**.
- الملاحظة اللافتة: المعاينة **تُحدَّث تلقائيًا** — كلما غيّرت أي حقل في النموذج أو أي إعداد في CMS، تُحدَّث المعاينة خلال نصف ثانية.
- زر **«فتح في نافذة جديدة»** ينقل المعاينة إلى صفحة مستقلة بعنوان `/preview`.

### التصدير
- زر **«تصدير CSV»** يُنزّل ملفًا يحتوي كل المشتركين (الاسم، الهاتف، الآيبان، مبلغ الاشتراك، الأرباح، الرسوم، الحالة، تاريخ الانضمام، البنك، العملة، المنصة).

### البيانات التجريبية
- زر **«تحميل بيانات تجريبية»** يضيف مشتركًا نموذجيًا كاملًا («أكرم هيج») يحتوي: بيانات النموذج (اشتراك 15,000 USDT، أرباح 4,200، رسوم 150، آيبان، رقم حساب، محفظة Binance/USDT/TRC20، بنك الراجحي)، 5 عمليات، **وتصميم CMS كامل بجميع الأقسام الـ 28**.
- هذا الزر ممتاز لفهم كيف تتكامل البيانات مع التصميم دفعة واحدة.

## إدارة قائمة المشتركين

أسفل نموذج الإضافة توجد **قائمة المشتركين** مع:

- **بحث فوري** (بالاسم/الهاتف/الآيبان).
- **ترقيم صفحات** (10 مشتركين لكل صفحة).
- **توسيع صف** لمشاهدة التفاصيل المختصرة.
- **زر تعديل** يعيد تحميل بيانات المشترك وتصميم CMS في النموذج مع استعادة خطوات المحفظة.
- **زر حذف** مع نافذة تأكيد («حذف نهائي ولا يمكن التراجع»).
- **زر إلغاء التعديل** للعودة إلى وضع الإضافة الجديدة.

# الجزء الثاني: نظام CMS (استوديو تصميم تطبيق العميل)

## مفهوم CMS

**CMS** هو استوديو تصميم متكامل يجعل كل مشترك يملك تطبيقًا مستقلًا تمامًا بخصوصية تصميمه ومحتواه. الفكرة:

```
المشترك → إعدادات CMS مخصصة → تطبيق عميل فريد
```

**المبادئ الأساسية:**

## النسخ بين المشتركين والقوالب

# الجزء الثالث: نظام الاستعلام

## شاشة الاستعلام

تظهر كوحدة «نظام الاستعلام عن الأرباح». تتكوّن من واجهة بحث داكنة راقية فيها:
- **هوية الشركة/الجهة** (الشعار والاسم والعنوان) — مأخوذة من **إعدادات تجربة بوابة المشترك** العامة.
- **حقل بحث واحد** يقبل عدة مفاتيح، وزر «استعلام الآن».
- **مؤشرات KPI** أعلى الواجهة: إجمالي المشتركين، النشطون، الرسوم المستحقة.
- **مفاتيح البحث المدعومة** تظهر كتلميحات تحت الحقل.

## البحث الموحّد

يبحث النظام في **مشترك واحد** بفحص أي تطابق مع قيمة الإدخال عبر هذه الحقول مجتمعة:

| الحقل | ما يبحث عنه |
|-------|------------|
| الاسم | الاسم الكامل (أي جزء منه) |
| الآيبان IBAN | رقم الآيبان |
| رقم الحساب | رقم الحساب البنكي |
| رقم الهاتف | الرقم مع وبدون البادئة |
| رمز الدولة | رمز الهاتف الدولي |
| حساب النظام | نص حساب النظام أو قيمته |
| عنوان المحفظة | العنوان الكامل أو القيمة |
| المنصة / البنك | اسم منصة المحفظة أو البنك |

- عند الضغط على «استعلام الآن» يُعرض **شريط تقدم** (مع تنبيه «جارٍ الفحص عبر قاعدة البيانات») ثم تظهر النتيجة.
- إذا لم يوجد تطابق: شاشة «لم يُعثر على مشترك مطابق» مع نص البحث المُدخل.

## نتيجة الاستعلام (ملف المشترك الكامل)

عند العثور، يعرض النظام ملفًا متكاملًا على مراحل:

1. **بطاقة الملف الشخصي** (شريط هوية داكن): الاسم، شارة «موثّق»، حالة المشترك، تاريخ الانضمام، نص المطابقة، وعدد العمليات المسجّلة.
2. **بيانات المشترك** (شبكة): الجوال، الآيبان، رقم الحساب، البنك، حساب النظام، العملة، المنصة، منصة المحفظة، دولة البنك — **مع احترام إعدادات الإظهار/الإخفاء**.
3. **ملاحظات إدارية** إن وُجدت (بطاقة صفراء).
4. **الملخص المالي** (بطاقات ملوّنة): مبلغ الاشتراك، الأرباح، رسوم النظام، والمحفظة الرقمية (مع زر إظهار/إخفاء العنوان الكامل).
5. **تجربة بوابة المشترك المخصصة**: تظهر مباشرة بعد الملخص المالي — وهي أقسام وأزرار مُعدّة **عامة** لكل البوابة.
6. **مُطلِق تطبيق العميل (CMS)**: بطاقة بنفسجية «تطبيق العميل — تجربة CMS مستقلة» تعرض زر **«فتح التطبيق»** لإطلاق تجربة بملء الشاشة.
7. **سجل عمليات المشترك**: جدول كامل بالعمليات (مرقّمة، مع ترقيم صفحات).
8. **خدمة سحب الأرباح**.
9. **طباعة وتصدير ملف المشترك** (قائمة طباعة).
10. **سجل جميع العمليات** (لوحة عامة لكل النظام).

## خدمة سحب الأرباح

سلسلة حالات تبدأ وتنتهي داخل شاشة الاستعلام:

```
حالة خاملة (زر سحب الأرباح)
      │
      ▼
تأكيد (هل تريد تأكيد طلب السحب؟)
      │
      ▼
معالجة (شريط تقدم 20 ثانية)
      │
      ▼
اكتمال (رسالة) —— يعرض نص السحب الخاص بالمشترك
      │      إذا لم يُدخل نص سحب → تظهر رسالة «لا يوجد نص سحب مُدخل»
```

> **ملاحظة:** النص الذي يظهر في مرحلة الاكتمال هو **نص السحب** الذي أُدخل في قسم إضافة المشترك (أو الرسالة الافتراضية). لذلك يُنصح دائمًا بتعبئته ليظهر للعميل.

## الخصوصية في الاستعلام

- بعض الحقول يملك كلٌّ منها زر إظهار/إخفاء في نموذج الإضافة (الهاتف، الآيبان، رقم الحساب). عند إخفائها، **لا تظهر** في ناتج الاستعلام.
- تطبيق العميل (CMS) يعرض اسم العميل حسب «اسم العرض» (أصلي/مستعار/مخفي) ويُخفي الهاتف جزئيًا أو كليًا حسب إعداد «الهاتف» في الملف الشخصي.
- المحفظة الرقمية تُعرض جزئيًا في الملخص المالي مع زر «عرض العنوان الكامل».

# الجزء الرابع: العلاقة بين إضافة المشترك + CMS + الاستعلام

## خريطة البيانات من الإدخال إلى العرض

| تُدخل في **إضافة المشترك** | يظهر في **نظام الاستعلام** | يظهر في **تطبيق العميل (CMS)** |
|---------------------------|------------------------------|--------------------------------|
| الاسم | بطاقة الملف الشخصي + شارة موثّق | اسم العرض في البطاقة والواجهة |
| الهاتف (ببادئة/إظهار) | حقل الجوال (إن كان ظاهرًا) | رقم الهاتف حسب إعداد «الهاتف» في الملف الشخصي |
| الآيبان (إظهار/إخفاء) | حقل الآيبان (إن كان ظاهرًا) | ضمن تفاصيل الحساب (إن ظهر) |
| رقم الحساب (إظهار/إخفاء) | حقل رقم الحساب | ضمن تفاصيل الحساب |
| مبلغ الاشتراك + العملة | بطاقة «مبلغ الاشتراك» | بطاقة مالية + المحفظة + الفاتورة |
| الأرباح + العملة | بطاقة «الأرباح» | بطاقة مالية + «أرباحي» + الرسوم/العدّادات |
| رسوم النظام + العملة | بطاقة «رسوم النظام» | بطاقة مالية |
| حساب النظام | حقل «حساب النظام» | ضمن تفاصيل الحساب |
| عنوان المحفظة | بطاقة المحفظة (مع زر عرض) | قسم «المحفظة الرقمية» |
| البنك | حقل البنك + دولة البنك | ضمن تفاصيل الحساب |
| المنصة | حقل المنصة + منصة المحفظة | ضمن تفاصيل الحساب |
| حالة المشترك | شارة الحالة | حالة البطاقة/القائمة الجانبية |
| ملاحظات | بطاقة ملاحظات إدارية | — |
| نص السحب | رسالة الاكتمال في خدمة السحب | رسالة السحب داخل التطبيق |
| العمليات المرفقة | سجل عمليات المشترك | جدول العمليات + الرسوم |
| **تصميم CMS (28 قسمًا)** | **مُطلِق «فتح التطبيق»** | **تطبيق العميل الكامل** |

## مفاتيح الربط بين المكونات

1. **المشترك يحمل تصميمه:** كائن المشترك يتضمن كائن `cms` كاملًا. لهذا كل مشترك له تطبيق مستقل.
2. **العمليات تُربط باسم المشترك:** كل سجل عملية يحمل «اسم المشترك»؛ وعند البحث تُجلب العمليات التي تطابق هذا الاسم. لهذا تغيير الاسم في التعديل يُحدّث العمليات تلقائيًا.
3. **البحث يقارن قيمًا لا مفاتيح** في عدة حقول؛ فيكفي أن يطابق أي حقل.
4. **بوابة المشترك (عامة) منفصلة عن تطبيق العميل (خاصة):** إعدادات «تجربة بوابة المشترك» تُطبَّق على كل نافذة استعلام، بينما CMS خاص بكل مشترك.

## تجربة بوابة المشترك (الإعداد العام) مقابل CMS (إعداد كل مشترك)

| الأوجه | تجربة بوابة المشترك (عامة) | CMS (خاص بكل مشترك) |
|--------|------------------------------|----------------------|
| أين يُعدَّل | أعلى قسم إضافة المشترك (مُنشئ هوية البوابة) | استوديو 28 قسمًا أسفل النموذج |
| نطاق التأثير | كل نافذة استعلام (تسمية/شعار/أقسام/أزرار عامة) | تطبيق المشترك نفسه فقط |
| ما يوفره | اسم الشركة، الشعار، عنوان البوابة، أقسام وأزرار توجيهية | التصميم الكامل: هوية، ألوان، أقسام، ويدجتات… |
| أين يظهر | أعلى ناتج الاستعلام (SubscriberQueryExperience) | تجربة بملء الشاشة تُفتح من زر «فتح التطبيق» |

> الخلاصة: **الواجهتان منفصلتان بتصميم مقصود** — بوابة الاستعلام تُؤطّر العرض، أما تطبيق العميل فهو المنتج النهائي الذي يخص المشترك وحده.

**المرحلة 1 — الإدخال (إضافة المشترك):**
1. يكتب الاسم «سالم»، ويختار دولة الهاتف (+966) ويدخل الرقم مع الإبقاء على «إظهار».
2. يُدخل الآيبان ورقم الحساب (يعتمد النظام لاحقًا على تأكيدهما عند الحفظ).
3. يُدخل مبلغ الاشتراك 20,000 بعملة USDT، والأرباح 5,000 بعملة USDT، ورسوم 200.
4. يملأ حساب النظام (يدوي بنص مميز)، وتاريخ الانضمام، والحالة «نشط».
5. يختار البنك من القائمة (أو يكتبه يدويًا)، والمنصة، والعملة الرئيسية.
6. يكتب ملاحظات قصيرة و**نص السحب**.
7. يضيف عمليتين للمشترك (توزيع أرباح + اشتراك جديد).

**المرحلة 2 — التصميم (CMS):**
8. يفتح استوديو CMS ويختر قالب «فاخر ذهبي».
9. يضبط هوية الشركة (اسم/شعار)، وملف المشترك (لقب + شارة VIP)، والشريطين العلوي والسفلي، وعناصر القائمة الجانبية.
10. يضيف نصوصًا ترحيبية وقسمًا مخصصًا «خطة الاستثمار» بصور وبطاقات معلومات ورسوم بيانية.
11. يُعاين النتيجة من زر «معاينة حية» ويضبط الشكل حتى يرضى.

**المرحلة 3 — الحفظ:**
12. يضغط «إضافة المشترك».
13. تجري الرقابات: فحص تكرار (لا يوجد)، ثم نافذة تأكيد الآيبان (يوافق على الحفظ)، ثم تأكيد رقم الحساب (يوافق).
14. يُدمج الهاتف مع البادئة، تُنظَّف العملات، يُجمَّع حساب النظام وعنوان المحفظة.
15. يُحفظ المشترك بتصميمه (CMS) + تُحفظ العمليتان مربوطتين باسم «سالم».

**المرحلة 4 — الاستعلام:**
16. من تبويب «نظام الاستعلام» يكتب المدير «سالم» في الحقل.
17. يمرّ شريط التقدم ثم تظهر البطاقة: الاسم + حالة + بيانات + ملخص مالي (الاشتراك/الأرباح/الرسوم/المحفظة).
18. تظهر «تجربة بوابة المشترك» العامة (اسم الشركة + الأقسام والأزرار الإرشادية).
19. يظهر زر «فتح التطبيق» — يضغط فيُفتح تطبيق العميل بملء الشاشة بتصميمه الذهبي الخاص.
20. يظهر سجل عمليات «سالم» (العمليتان)، ثم يختبر «سحب الأرباح» فيظهر **نص السحب** الذي كتبه في المرحلة 1.

# المرجع السريع: أين تُخزَّن الأشياء؟

| المخزن | الغرض |
|--------|-------|
| المشتركون | كل بيانات المستثمرين + تصميم CMS لكل مشترك |

## الخلاصة

- **إضافة المشترك** هو نقطة الدخول: تُدخل البيانات الحساسة والمبالغ والحسابات، وتُرفق عمليات، وتبني تطبيقًا كاملًا.
- **CMS** هو «مصنع التطبيق»: 28 قسمًا اختياريًا يتحكّم في شكل ومحتوى ما يراه العميل، مع قوالب ونسخ بين المشتركين.
- **نظام الاستعلام** هو المنفذ: يعرض الملف، ويحترم إعدادات الخصوصية، ويفتح تطبيق العميل، ويعرض العمليات، ويقدم خدمة السحب بنص مخصص.
- **العلاقة بينها** محكمة عبر ثلاث روابط: (1) المشترك يحمل تصميمه، (2) العمليات تُنسب بالاسم، (3) بوابة الاستعلام العامة منفصلة عن تطبيق العميل الخاص.

> **تذكّر:** كل حقل اختياري، وكل قسم قابل للتفعيل/الإطفاء، والخصوصية (إظهار/إخفاء) تُفعَّل من نموذج الإضافة وتنعكس في الاستعلام. صمّم كل مشترك على حدة لأنه تطبيقه المستقل. 🚀
